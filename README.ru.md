# Engram

**[English](README.md)** · **[Русский](README.ru.md)**

**Долговременная память для агентов: запись после хода, изоляция по контурам и доказуемость через квитанции.**

Engram — система памяти для [OpenClaw](https://github.com/openclaw/openclaw), рассчитанная на личных агентов, проектные чаты и команды агентов. В центре актуальной архитектуры — **Memory Worker**: постходовый конвейер, который превращает завершённые диалоги в компактную операционную память и не требует от foreground-агента каждый раз помнить о записи.

- автоматический захват событий и решений;
- строгая изоляция workspace и сессий;
- crash-safe очереди, неизменяемые наблюдения и квитанции с read-back;
- Knowledge Graph v3 для явных долговременных утверждений;
- гибридный поиск через QMD (BM25 + embeddings + rerank);
- domain-память для проектов, топиков, групп и субагентов.

**MIT · OpenClaw · v3.6.5**

## Зачем нужен Engram

Агенты теряют непрерывность на `/new`, после compaction и при переходе между эфемерными воркерами. Загрузка всей истории чата только откладывает проблему: растёт расход токенов, полезный сигнал тонет в шуме, а приватные контуры становится трудно разделять.

Engram сохраняет активный промпт небольшим, а историю — доступной для поиска в разрешённом контуре.

| Проблема | Без Engram | С Engram |
|---|---|---|
| Новая сессия стартует «холодной» | Нужно перечитывать или копировать чаты | Компактная daily/domain-память извлекается поиском |
| Агент забыл записать результат | Важный контекст исчезает | Memory Worker оценивает завершённые ходы |
| Память превращается в свалку текста | Низкая точность и растущий расход токенов | Типизированный захват, квитанции и гибридный поиск |
| Проектные контуры смешиваются | Случайный доступ к чужому контексту | Точные границы сессий и коллекций |
| Фоновая обработка частично упала | Тихие пробелы или дубли | Устойчивые очереди, идемпотентные эффекты и явное здоровье |

## Актуальная архитектура

Engram разделяет **операционную память**, **долговременные знания** и **поиск**. Они связаны, но не делят полномочия на запись.

![Архитектура Memory Worker: операционная память и долговременные знания используют разные пути записи](assets/readme/engram-memory-worker-architecture.webp)

Ключевая граница проведена намеренно:

- **Memory Worker записывает, что произошло.** Он владеет операционными Events и Decisions только в явно активированных контурах.
- **KG v3 хранит то, что должно остаться актуальным долговременным утверждением.** Он принимает только явные авторизованные typed-записи из исходного хода.
- **QMD — производный слой поиска.** Он индексирует каноническую память, но не становится источником истины.
- **Heartbeat обслуживает workspace.** После перехода на KG v3 он больше не классифицирует daily notes и не продвигает их в граф.

Автоматическое продвижение наблюдений в KG отключено. Того, что модель заметила факт в разговоре, недостаточно для изменения долговременного знания.

## Memory Worker

Memory Worker — основной путь захвата в активированных личных и проектных контурах.

### 1. Захват завершённого хода

Интеграция OpenClaw связывает доверенные идентификаторы сообщения, сохранённого хода, запуска и завершения. До оценки она фиксирует checkpoint, хранит только ограниченный объём evidence, скрывает учётные данные и отклоняет сырые результаты инструментов, медиа и вложения.

Гарантия восстановления после сбоя начинается с момента устойчивой записи первого checkpoint. Сбой хоста до вызова hook остаётся за границей Engram, и система никогда не выдаёт такой ход за восстановленный.

### 2. Оценка эпизода

Worker использует изолированный evaluator без инструментов. Он формирует ограниченный набор компактных утверждений для `events` или `decisions`, а для каждого принятого источника сохраняет явный disposition: `asserted`, `supports`, `duplicate`, `skip` или `unresolved`.

Контекстный evaluator v2 умеет объединять ограниченный локальный эпизод, различать авторов и сохранять статус: `requested`, `decided`, `reported_done`, `accepted` или `failed`. В наблюдении остаются точные фрагменты источника; confidence не может отменить проверки контура и полномочий.

### 3. Запись с доказательством

Отдельный детерминированный consumer записывает допущенную запись в правильную daily note. Каждая запись получает:

- непрозрачный Markdown-anchor;
- неизменяемую apply-квитанцию;
- точный provenance источника, контура, producer и policy;
- read-back назначения перед завершением;
- идемпотентное восстановление после сбоя.

В topic-workspace второй consumer через join квитанций проецирует проверенные записи в domain-changelog и recent status. Он не запускает модель повторно и не создаёт второй источник истины.

### 4. Передача в поиск

После канонической записи Engram публикует не содержащий контента QMD handoff с dirty-generation. Глобальный coordinator выполняет `update` и инкрементальный `embed`, а затем фиксирует `canonical_indexed` только после точного read-back коллекции, документа, anchor, digest и физического индекса.

Engram не заявляет retrieval и utilization без доказательства от хоста. Состояния **captured**, **applied**, **indexed**, **retrieved** и **used** разделены, а не склеены в один оптимистичный «успех».

### Явное владение записью

Memory Worker активируется через rollout-проекцию, закреплённую за digest. Пока проекция невалидна, выключена, не охватывает текущий контур или ещё не достигла границы активации, запись остаётся за foreground-агентом. После передачи владения foreground-записи в Events/Decisions отклоняются, чтобы не возникали дубли.

То же правило действует для ограниченного семейства агента: у каждого принятого источника и каждой записи сохраняется точный runtime-session scope.

## Knowledge Graph v3

KG v3 — слой долговременных утверждений, а не пересказ всего, что увидел Worker.

- Запись выполняется через `engram_memory_save` или `engram_memory_retract` в авторизованном исходном ходе.
- Реестры сущностей и предикатов работают fail-closed.
- За один исходный ход допускается не более одной typed-мутации.
- Утверждения неизменяемы и привязаны к provenance.
- Исправления образуют явную цепочку replacement/supersession; история сохраняется.
- Legacy-хранилище v2 `items.json` неизменяемо, fallback-writer отсутствует.

Фактическое использование утверждений отдельно фиксируется через `engram_memory_access`. Ежедневный coordinator применяет события к access-state overlay и перестраивает decay-aware проекцию `life/v3/current-summary.md`, не изменяя канонические тела утверждений.

| Tier | Свежесть | Current summary | Доступность в поиске |
|---|---:|---|---|
| **Hot** | ≤ 7 дней | заметно | да |
| **Warm** | 8–30 дней | ниже приоритет | да |
| **Cold** | 30+ дней | исключено | да, через QMD |

## Домены и командная память

Домены дают эфемерным воркерам и долгоживущим чатам устойчивый ограниченный контекст.

![Реестр доменов: каждая сессия разрешается в один ограниченный домен](assets/readme/engram-domain-addresses.webp)

| Тип домена | Binding | Типичное применение |
|---|---|---|
| `topic-thread` | forum topic | проектный канал с курируемой памятью |
| `peer-direct` | DM | приватный контур 1:1 |
| `group-direct` | group | общий групповой контур |
| `dev-project` | KG entity | инженерная работа и запускаемые субагенты |
| `cron-task` | schedule | фоновые воркеры с durable state |

Topic-домены хранят `decisions.md`, `status.md` и `changelog.md`. Domain-контекст подключается при bootstrap, а не копируется в каждый промпт и не открывается соседним проектам.

В уже подключённом проектном workspace создание topic-domain — одна возобновляемая операция: вместе проверяются запись в registry, host route, точные QMD-коллекции и binding Memory Worker.

## Надёжность и безопасность

![Устойчивая к сбоям доставка: каждый переход от завершённого хода до индекса QMD подтверждается checkpoint или квитанцией](assets/readme/engram-crash-safe-pipeline.webp)

Engram рассматривает память как последовательность проверяемых переходов, а не как одну оптимистичную фоновую задачу. Завершённый ход становится восстанавливаемым после устойчивого checkpoint; каноническая запись и индексация завершаются только после собственной квитанции и точного read-back.

| Свойство | Как это обеспечивает Engram |
|---|---|
| **Нет двойной записи** | явная передача ownership + идемпотентные operation identities |
| **Нет fallback между контурами** | точные workspace/session bindings и точное разрешение QMD-коллекций |
| **Восстановление после сбоя** | устойчивые checkpoints, очереди, leases, неизменяемые квитанции и read-back назначения |
| **Ограниченный evidence-контур** | редактирование секретов, лимиты размера, TTL и запрет сырых tool/media payloads |
| **Нет тихого продвижения в KG** | отдельные полномочия typed KG v3; observer не умеет мутировать KG |
| **Видны частичные сбои** | учёт по workspace и здоровье fleet; cron `ok` не считается семантическим успехом |
| **Безопасный rollback** | проекцию можно отключить, сохранив очереди, квитанции и канонические данные |

Срок хранения зависит от класса артефакта: сырой evidence живёт недолго, а не содержащий контента provenance и квитанции — дольше, чтобы записанную память можно было проверить после удаления evidence.

## Сопутствующие сервисы

### QMD

QMD обеспечивает гибридный поиск с контролем контуров:

- BM25 для точных терминов;
- embeddings для семантической близости;
- reranking для финальной релевантности;
- один координируемый физический индекс для множества логических коллекций.

Каждый agent-facing поиск требует хотя бы одну явную `-c <collection>`. Перед выполнением проверяются ownership коллекции и разрешённая область чтения.

```bash
bun bin/engram --workspace /path/to/workspace \
  qmd query "search text" -c workspace-memory -c workspace-life
```

Публичных `engram qmd update/embed` и generic passthrough намеренно нет. Обслуживание индекса принадлежит coordinator.

### Heartbeat

Heartbeat теперь детерминированный maintenance-runner. Он обслуживает locks, ротацию и watermarks daily notes, домены, валидацию и отчётность. Извлечение и автоматическое продвижение в KG отключены; обслуживание QMD может быть делегировано глобальному coordinator.

### Operational Learning Loop

OLL наблюдает разрешённые friction-, correction-, preference-, workflow- и quality-сигналы. Отдельный nightly coordinator выполняет reconciliation и ограниченную адаптацию. Правила привязаны к контуру и квитанциям, поддерживают rollback и подключаются только тогда, когда активная проекция соответствует текущему контексту.

Материализация правил из памяти — отдельный gated-контур; обычная запись Memory Worker не превращается в инструкцию автоматически.

## Быстрый старт

Требования:

- [OpenClaw](https://github.com/openclaw/openclaw);
- [Bun](https://bun.sh) ≥ 1.3 и < 2;
- QMD в локальном или облачном режиме.

Инициализация workspace:

```bash
# Установить движок гибридного поиска
bun skills/engram/scripts/install-qmd.js

# Сначала посмотреть план
bun skills/engram/scripts/init.js \
  --workspace /path/to/workspace \
  --agent-id main \
  --qmd-variant auto \
  --with-cron \
  --dry-run

# После проверки применить
bun skills/engram/scripts/init.js \
  --workspace /path/to/workspace \
  --agent-id main \
  --qmd-variant auto \
  --with-cron
```

Init создаёт структуру памяти workspace, устанавливает managed-набор hooks, при необходимости перезапускает gateway, проверяет hook read-back и может подготовить отключённый до проверки maintenance-cron.

**Memory Worker активируется отдельно.** Init не угадывает membership во fleet, source scopes, полномочия модели, QMD bindings и одобренную оператором границу активации. Используйте проверенное rollout-tooling и deployment-runbook своего окружения, а затем подтвердите installed plugin digest, проекцию, scheduler, каноническую квитанцию/read-back и реальный scoped-поиск через QMD.

Аудит workspace без правок:

```bash
bun skills/engram/scripts/watchdog.js \
  --workspace /path/to/workspace \
  --json
```

Scaffolding, пустой проход Worker или scheduler `ok` не являются end-to-end доказательством.
